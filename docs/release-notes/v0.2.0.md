# v0.2.0 Journal Mirror Agent

Status: release candidate; ready to tag only after this PR merges and the release checklist passes. This document does not indicate that a `v0.2.0` tag or GitHub release exists.

## Summary

`v0.2.0` turns the public scaffold into a coherent, manually usable Journal Mirror handoff. A user writes in a private notes system, selects a small amount of context, runs a prompt-guided reflection, and reviews any separate Memory or State proposals before manually copying approved wording. The repository remains a public control plane; private notes and runtime artifacts remain in a user-controlled data plane outside Git.

## What Changed Since v0.1

- Defined the Journal Mirror runtime pattern: natural private writing, explicit context selection, tentative reflection, and reviewed updates.
- Added a private Obsidian/private-notes guide that is usable without a plugin or server.
- Added prompt and session surfaces for freeform entries, selected-context sessions, recent-pattern reviews, gentle next actions, and proposal review.
- Added capability modules with privacy-first trust metadata and no-vault-access boundaries.
- Added separate review-only Memory and State proposal schemas.
- Added synthetic proposal lifecycle examples and Journal Mirror walkthroughs.
- Expanded synthetic safety, privacy, proposal, and future-controller boundary evals.
- Added a future MCP/VPS controller contract as a design-only specification.
- Added a usable-product handoff, release checklist, and release-focused navigation.
- Added conservative line-ending normalization and ignored the local `.agents/` scratch workspace.

## What Is Usable Now

- Manual, private-first Journal Mirror sessions using context the user deliberately selects.
- Prompt-guided, tentative, non-clinical reflection over one entry, excerpt, or small selected group.
- Optional, separate Memory and State proposals that remain inert pending human review.
- Manual copying of exact approved wording into private Memory or State.
- Synthetic walkthroughs and manual evals for inspecting the intended flow and boundaries.

Start with the [usable-product handoff](../v0.2-usable-product-handoff.md) and [private runtime guide](../obsidian-private-runtime-guide.md).

## Intentionally Not Included

- No live runtime, hosted service, or app backend.
- No MCP server or VPS controller implementation.
- No Obsidian plugin, vault reader, or broad notes access.
- No automatic Memory or State writes and no automatic State-to-Memory promotion.
- No crisis automation.
- No therapy or clinical product, diagnosis, treatment planning, medication guidance, or claim of therapeutic effectiveness.

## Public / Private Boundary

The public repository is the reusable control plane: instructions, guardrails, prompts, schemas, templates, synthetic examples, evals, release documentation, and validation tools. The private notes system is the data plane: real entries, selected excerpts, reflections, pending proposals, approved Memory, current State, exports, and any private runtime records.

Private artifacts must remain outside Git. Public examples must be synthetic. Memory is durable, explicitly approved context; State is temporary context with a review, stale, or expiration trigger. Proposals for either destination are review-only and do not authorize persistence.
