# v0.3 Usable-Product Handoff

## What This Is

Journal Mirror `v0.3.0` is a local/private MCP runtime prototype built on a file-first scaffold. The public repository is the reusable control plane—code, prompts, schemas, guardrails, tests, and documentation—while an initialized user-controlled vault outside the repository is the private data plane. It is not a hosted app.

## Who It Is For

- Builders studying private-first journal, Memory, and State runtime design.
- Users comfortable managing local files, Python commands, and MCP setup.
- People who want explicit context selection and review-gated persistence rather than automatic retention.

It is not for people seeking turnkey therapy, diagnosis, medical advice, treatment planning, medication guidance, crisis counseling, or emergency support.

## What You Can Do in v0.3.0

- Initialize a blank private vault outside the repository.
- Use guided intake to create separate reviewable pending Memory and State proposals.
- Run a local stdio MCP server against one explicit initialized vault.
- Read one selected session file and approved Memory/current State allowlists.
- Create pending Memory or State proposals without applying them.
- Review, approve, reject, defer, or expire proposals.
- Apply character-exact approved wording to a matching allowlisted Memory or State file after destination-specific confirmation.
- Inspect bounded local runtime metadata with an optional static viewer.
- Run automated tests and manual synthetic evals.

## Safe First-Run Path

1. Read [Privacy](../PRIVACY.md), [Security](../SECURITY.md), and [Guardrails](../GUARDRAILS.md).
2. Clone this public repository. Do not use the repository itself as the vault.
3. Choose an absolute private-vault location outside the repository and outside any public sync/share location.
4. Follow the [private-vault runtime package](private-vault-runtime-package.md): run the initializer with `--dry-run`, review the plan, then run the actual initialization.
5. Inspect the generated folder structure and generic starter files. Confirm that Memory, State, pending proposals, sessions, audit records, and exports have separate locations.
6. Run the [validation quickstart](#validation-quickstart) with synthetic fixtures.
7. Run `python -m mcp_server.journal_mirror_server --help` and `python -m viewer.local_runtime_viewer --help`; help must exit without reading or writing private data.
8. Optionally follow the [ChatGPT connector setup](chatgpt-mcp-connector-setup.md). Local stdio alone is not directly reachable by ChatGPT; connectivity must be configured and reviewed separately, and nothing from that configuration belongs in this repository.
9. Use the [first-run walkthrough](first-run-chatgpt-walkthrough.md): start with the no-read tool inventory prompt, then one selected read and separate allowlisted Memory/State reads.
10. Run the broad-scan and silent-write refusal tests.
11. Create separate synthetic pending Memory and State proposals; verify proposal creation does not approve or apply wording.
12. Only after earlier checks pass, test review and exact apply with character-exact synthetic wording, a named destination, an allowlisted target, and the destination-specific confirmation.
13. Optionally follow the [viewer guide](local-runtime-viewer.md) to render HTML into an explicit protected private output path outside the repository.

## What to Keep Private

- The initialized private vault and all real raw journal entries.
- Filled Memory and live State files.
- Selected session context and generated reflections.
- Pending proposals, approval metadata, and audit records.
- Connector configuration, private endpoints, connectivity profiles, and tunnel details.
- Generated viewer HTML, screenshots, logs, and exports.
- Credentials, tokens, local identifying paths, and device/sync/backup details.

Private storage is not automatically confidential. Device permissions, local processes, sync, backup, retention, sharing, and connectivity remain the user's responsibility.

## What Not to Do

- Do not place a private vault inside this repository or commit generated output.
- Do not expose the local server publicly without a separately reviewed security plan.
- Do not approve read or write tool calls blindly; inspect complete payloads.
- Do not use this prototype as a replacement for therapy, licensed care, medical support, crisis counseling, or emergency services.
- Do not automatically store crisis narratives, diagnostic interpretations, treatment directions, or medication guidance.
- Do not let temporary State silently become durable Memory.
- Do not treat prompt text, proposal creation, schema validation, or client confirmation alone as authorization.
- Do not weaken exact-wording, destination, lifecycle-trigger, target-allowlist, or repeat-apply checks to make a refusal disappear.

## Validation Quickstart

From the public repository root:

```text
python scripts/validate-json-schemas.py
python -m unittest discover -s tests
python -m mcp_server.journal_mirror_server --help
python -m viewer.local_runtime_viewer --help
```

Expected baseline: 9 schemas and 79 tests; both help commands exit successfully without starting runtime behavior. Use the [runtime validation checklist](runtime-validation-checklist.md) for suite-specific commands and safety scans. The [release checklist](release-checklist-v0.3.0.md) records the historical pre-tag gate, and the [final public-safety verification](release-verification/v0.3.0-final-public-safety-verification.md) records issue #46.

Manual evals in [EVALS.md](../EVALS.md) are qualitative synthetic boundary checks. They are not proof of production safety, security, privacy, clinical suitability, or effectiveness.

## Troubleshooting

| Symptom | Safe response |
|---|---|
| A Python dependency is missing | Install the reviewed dependencies from `requirements.txt` in an isolated environment; do not add credentials or private configuration to the repository. |
| Initializer refuses a vault inside the repository | Expected. Choose an explicit absolute path outside the repository; do not bypass the check. |
| ChatGPT cannot connect to the local stdio process | Expected. ChatGPT needs a separately reviewed supported connectivity path; this repository supplies no adapter, endpoint, or connector configuration. |
| Exact apply is refused | Compare reviewed proposal status, destination, character-exact wording, confirmation phrase, and allowlisted target. Do not loosen the gates. |
| State apply is refused | Confirm the proposal has both review/stale and expiration triggers in addition to the normal approval requirements. |
| Viewer output path is refused | Choose an existing protected output parent outside the public repository and use explicit absolute paths. |
| Tests print malformed JSON warnings | Expected only in the synthetic malformed-input cases; confirm the suite still passes and no generated files remain. |
| ChatGPT tools are unavailable | Account/workspace controls and current product availability may not support custom MCP tools. Keep using the local/manual flow or stop; do not publish a private endpoint as a workaround. |

## Success Criteria

- A user can initialize a blank private vault outside the repository.
- A user can run schema validation, tests, and help commands.
- A user can explain what the runtime reads, writes, and refuses.
- A user can create and review separate synthetic Memory and State proposals.

- A user can keep the public control plane, private data plane, connectivity material, and generated outputs separate.
